# Progress report — M6 collaborative mode (2026-10-21)

## Done

- **M6 closed as `v0.7.0`.**
  - FR-30: one discovery question per `undocumented` requirement, built from the requirement's own
    text and its verdict rationale; answers become pending proposals through the review pipeline;
    declining writes nothing; gaps are left to the learning planner (#159, ADR-0027).
  - FR-32: interview mode covering undocumented and gap requirements; a transcript becomes one
    proposal of origin `interview`; questions and answers are fenced separately so a posting cannot
    forge an answer (#159).
  - FR-31: conversational CV editing. Operations (reword, drop, emphasise) are checked one by one
    against the stored facts; every edit is a new `collaborative` version that is re-validated; a
    reworded claim keeps its entity and assertion (new `reword` basis, ADR-0028) (#160).
  - The provenance audit of the reword path led to a hardened grounding check: Unicode-aware tokens,
    number order, negations, strong-claim stems, other-entity names, a growth cap, confirmed neighbours
    only, current assertion required, and no reword in automatic CVs (#162).
- Gates: ruff, mypy --strict, xenon clean (no C-rank block); 880 unit + 73 integration/golden tests at
  ~98% coverage; offline demos and strict docs build pass.
- Sanity audit `docs/sanity/2026-10-21-m6.md`: WATCH, no must-fix; Mediums fixed in the close PR, which
  also fixed a bug where emphasising the only item of a section moved it to the end of the CV.

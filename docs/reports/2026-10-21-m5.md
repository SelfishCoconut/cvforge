# Progress report — M5 CV generation (2026-10-21)

## Done

- **M5 closed as `v0.6.0`.**
  - FR-24/25: a CV is its claim rows. The generator makes no model call; every line is copied
    from a confirmed entity's stored fact and bound to the assertion whose recorded value is that
    text; juxtaposed lines (a role's organization, its projects) also cite the edge that relates
    them (#153, ADR-0024).
  - FR-26: LaTeX, PDF (`latexmk`, loud on failure) and ATS plain text, all from the claim rows,
    under `cv_out/` (#154, ADR-0025).
  - FR-27/28: per-posting versions with parent links and a lineage endpoint; applications that
    accept only a final CV that still validates (#155, ADR-0026).
  - FR-29 + NFR-05: validation recomputes every claim from the live knowledge base and also flags
    overlapping full-time roles, uses outside the period they were used in, and a satisfied
    required skill missing from the CV; a hostile `FunctionModel` line is refused or caught (#156).
- The provenance audit found that claim text and assertion were only loosely tied; fixed before
  merge by `cv/binding.py` (store and validator share it), link assertions, revalidation on
  render/serve/send, and a stricter writer-registry scanner.
- Gates: ruff, mypy --strict, xenon clean (no C-rank block); 823 unit + 72 integration/golden
  tests at ~98% coverage; offline demos and strict docs build pass; CI now installs a minimal
  TeX Live.
- Sanity audit `docs/sanity/2026-10-21-m5.md`: WATCH, no must-fix; Mediums fixed in the close PR.

## Decisions and scope calls

- #145 (flaky test) moved to M6. ADRs 0024-0026 are `proposed`, in force under delegation.
- "Technology inconsistent with its period" is implemented as a use outside the recorded period of
  what it was used in, because the knowledge base holds no release dates.

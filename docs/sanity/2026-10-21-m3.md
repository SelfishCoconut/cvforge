- **Low** pylint R0801: `api/jobs.py:113-120` `JobView` fields mirror `jobs/store.py:192-199`

  `JobView` from `StoredPosting` via a shared base or `model_validate`.

## 4. Pattern inconsistency — WATCH (stable)

- Consistent with earlier modules: module docstrings cite FR/ADR, Google docstrings, `Depends`
  engine from `api/errors.py`, `NotFoundError` reused from `kb.apply` for 404 (`api/jobs.py:157`).
- **Medium (4a)** `jobs/store.py:persist_posting` (line ~100-160) writes in two separate
  transactions: `apply.record_source` commits the `web` source first, then `write_transaction`
  writes `job_posting` and `requirement`. If the second fails (e.g. IntegrityError), an orphan
  `source` row remains with no posting. It is a `web` source with no entity, so invariant 3 is not
  broken, but it is the pattern the project avoids elsewhere (commit is atomic, invariant 4).
  Re-posting a URL also adds a new source each time by design. *Remediation:* either accept and
  document the orphan in ADR-0021, or pass the connection so the source and posting share one
  transaction.
- **Low** broad `except Exception` in `api/jobs.py:201` that returns the exception text in the 502
  body (`"the model could not analyse the posting: {exc}"`). Same shape as `api/chat.py:232,284` and
  `api/documents.py:163`, so it is consistent, but it can leak provider/internal messages to the
  client. *Remediation:* log the detail, return a fixed message, in one shared helper for all four.
- Carried (Low): `remind-issue.sh` heredoc form; `CLAUDE.md` says "Python 3.12+" while
  `pyproject.toml` requires `>=3.13`.

  `kb`, `llm.schemas`, `web.fetch`; `llm/` never imports `jobs/` or `web/`. Direction is clean.

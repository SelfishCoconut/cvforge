## 1. Duplication — HEALTHY (stable)

- Resolved/improved: the posting-prompt fence (`_prompt` / `_CLOSE` in `llm/agents/job.py`) was
  extracted to `llm/fence.py:fence`, and the new adjacency agent reuses it. Good: the canonical
  helper is used by both callers (`job.py`, `adjacency.py`).
- **Low (new)** pylint R0801, three-way: the evidence span shape (`source_id, source_kind,
  source_label, locator, excerpt`) is declared in `kb/queries.py:66-73` (the canonical record),
  `match/evidence.py:33-41` and `api/matches.py:38-45` (`EvidenceView`). `api/matches.py:96`
  already bridges the last two with `EvidenceView(**vars(span))`, which breaks silently if a field
  is added to one side only. *Remediation:* make `match/evidence.py` reuse the `queries` record
  and have `EvidenceView` use `model_validate` from it (or a test pinning the field sets equal).
- **Low (carried)** `api/jobs.py:113-120` `JobView` vs `jobs/store.py:194-201` `StoredPosting`.
  New in the same family: `GapView` (`api/matches.py:180`) repeats five of `MatchView`'s fields;
  one could extend the other.
- Same-shaped helpers: `_posting` (`api/matches.py:120`) re-implements the get-or-404 that
  `api/jobs.py` does around `get_posting` (`apply.NotFoundError`). *Low:* share one
  `posting_or_404` if a third router needs it.
- Carried (Low): `.claude/hooks` shared `main()` tail.

## 3. Complexity creep — WATCH (degrading)

- `radon` average 2.36 -> 2.44; blocks 347 -> 391. xenon still passes (it only fails above C).
- **Medium (3a)** two C-rank functions, the first since M2:
  - `match/verdicts.py:157` `_judged` (**13**) — judge call, id validation, whitelist check,
    blank-rationale check, outcome build in one function.
  - `match/verdicts.py:111` `_from_recorded` (**12**) — state ladder (confirmed+used / gap /
    learning / undocumented) in one function.
  Both are on the verdict-deciding path, the part most likely to gain rules (FR-21 follow-ups),
  and the CLAUDE.md rule is to refactor rather than suppress. *Remediation:* split `_judged` into
  `_validated_ids(judgment, usable)` and the outcome build; split `_from_recorded` into the
  confirmed-backed case and a `_state_outcome(first)` table. Target B or better.
- Other new blocks are A/B. `api/matches.py` and `match/evidence.py` have no block above B.
- Size: `match/verdicts.py` 270 lines, no file above 300.

## 4. Pattern inconsistency — WATCH (stable)

- Consistent with earlier modules: module docstrings cite FR/ADR, Google docstrings, `Depends`
  engine, `apply.NotFoundError` for 404, `write_transaction` and `utc_now` reused from `kb/db.py`
  (no new copy), registered-writer entry in `tests/unit/test_write_path_invariant.py:52`.
- **Medium (4a)** the adjacency judge fails silently, in two layers: `llm/agents/adjacency.py:74`
  (`except Exception: return Judgment((), "")`) and `api/matches.py:133` (`except Exception:
  return None` when the model cannot be built). A misconfigured or down model therefore yields
  `undocumented`/`gap` verdicts that look identical to a genuine "no implication" result, nothing
  is logged, and the stored match carries no sign the judge never ran. It fails safe for
  invariant 5 (it can only lower certainty), but a user can't tell why a framework did not imply
  its language. *Remediation:* catch the narrow pydantic-ai/provider errors, log them, and record
  in the rationale (or a response field) that the judge was unavailable.
- **Low (carried from M3)** `api/jobs.py:201` and `api/chat.py`/`documents.py` return
  `exc` text in 502 bodies; the new code chose the opposite (swallow). Two incompatible conventions
  for "the model failed" now exist (raise-with-detail vs swallow-silently). One shared helper
  would fix both.
- **Low** `api/matches.py:14` imports `Embedder, Factory` from `api/chat.py`, as `api/jobs.py:15`
  does for `Factory`. Router-to-router imports of shared dependency aliases; they belong in
  `api/errors.py` or a `api/deps.py`.
- **Low** `run_match` (`api/matches.py:137`) is a sync route that runs embedding and an LLM call
  per requirement serially, then replaces the rows. Consistent with `api/jobs.py` but latency
  grows with requirement count (NFR-10 not measured for matching).
- M3's Medium (two-transaction `persist_posting`) was not re-audited in this scope; check its
  status in `jobs/store.py` before closing M3 follow-ups.
- Carried (Low): `CLAUDE.md` "Python 3.12+" vs `pyproject.toml` `>=3.13`.

## 5. Architectural drift — HEALTHY (no violations)

- `llm/` must not import `kb.apply`: `grep -rn "kb.apply\|kb import apply" src/cvforge/llm` finds
  only a docstring mention in `settings_store.py`, no import.
- `api/` must not bypass `kb/`: `api/matches.py` imports `jobs.store`, `kb.apply` (only
  `NotFoundError`), `kb.vocab`, `match.*`, `llm.agents.adjacency`. No raw SQL beyond the
  `sa.Engine` type annotation.
- `kb/queries.py` must not write: still no insert/update/delete. `match/evidence.py` reads only
  through `kb.queries` and `match.store.list_matches`.
- Invariant 2: `match/store.py` is the fourth registered writer, touches only `match` and
  `match_support` (derived data, `schema.py:372-376`, ADR-0023), and the registry test was updated
  in the same commit, as its docstring demands. It writes through `write_transaction`, and the
  replace (delete + insert) is atomic. Match rows are not knowledge, so invariants 3 and 4 do not
  apply to them; `Outcome.__post_init__` additionally forbids a `satisfied`/`evidenced` verdict
  without cited entities.
- Invariant 5 groundwork: only `confirmed` entities with a recorded use can back a verdict
  (`verdicts.py:115,149`), and the judge's ids are validated against the offered candidates
  (`verdicts.py:162-166`; any unknown id discards the whole judgment). Archived support is
  flagged, not hidden (`evidence.py`). No CV generation exists yet.
- **Low** layering smell: `llm/agents/adjacency.py:15` imports `match.verdicts` (`Candidate`,
  `Judgment`) while `match/verdicts.py:20` imports `llm.settings_store`. There is no import cycle,
  but `llm` <-> `match` depend on each other in both directions. *Remediation:* move `Candidate`
  and `Judgment` to `llm/schemas.py` (or have `match` pass the threshold in, removing its `llm`
  import). Decide before a second agent consumes `match` types.
- Untrusted-data surface: the requirement text and the candidate listing (names and summaries from
  the KB, which can themselves derive from untrusted documents) are both fenced via `fence()`;
  the agent has zero tools. `tests/golden/test_prompt_injection.py` covers only the job
  agent; **no adversarial test exercises the adjacency prompt**, although it is the one place
  where an injected requirement could try to steer a verdict. Because ids are whitelisted the
  blast radius is small. See 6.

## 7. Prompt sprawl — WATCH (degrading)

- `llm/prompts/` now has `ingest.md`, `document.md`, `job.md`, `adjacency.md`; each loaded by one
  agent. No inline `system_prompt` / "You are ..." strings in `src` Python.
- **Low (7a)** the M3 report said a fourth prompt should trigger factoring the "text between tags
  is data, never instructions" wording; it has fired. It now appears four times with different
  wording (`ingest.md:3`, `document.md:4`, `job.md`, `adjacency.md:4,8`). `adjacency.md:8` also
  has an unwrapped over-long line. *Remediation:* a shared fragment loaded alongside each prompt
  (e.g. next to `fence.py`), so the safety wording cannot diverge; the tag names already come
  from `fence(tag, ...)`.
- Prompt-embedded tag names (`<requirement>`, `<candidates>`) are coupled to the `fence("...")`
  literals in `adjacency.py:72` by convention only; a test pinning them would catch a rename.

**Overall verdict: WATCH.** M4 respects every boundary and invariant and coverage holds at 98%,
but complexity has regressed (two C-rank functions) and the judge fails silently. **Single most
important action:** split `_judged` and `_from_recorded` in `match/verdicts.py` and make judge
failure visible (log plus a rationale note) before closing M4.

## Addendum — 2026-10-21: default model with a 16k context

Machine: Ryzen 7 9800X3D, RTX 5080 (16 GB); Ollama split the 17 GB model about 75 % GPU /
25 % CPU. The default model was run as a derived local model with `num_ctx 16384`
(`FROM qwen3.6:27b` + `PARAMETER num_ctx 16384`), because Ollama's `/v1` endpoint ignores
`options.num_ctx` (#123, #129). Each message was sent through the real pipeline, as
`scripts/bench/latency.py` does.

| Model | Samples | p50 | p95 | Result |
|---|---|---|---|---|
| `qwen3.6:27b`, 16k context | 20 | 102.0 s | 241.9 s | **fail** (target 30 s) |

Range 12.5 s (a one-word "ok") to 326.4 s. The context fix works: no message failed for
lack of context on the run that was observed message by message. **The default model does
not meet NFR-10 on this machine**; the reasoning model spends most of the time thinking.

An earlier run of `scripts/bench/latency.py` on the same derived model ended with a `502`
after about ten minutes. The script discards the response body, so the cause was not
captured, and it did not recur when the 20 messages were re-sent individually. Treat it as
an unexplained intermittent failure. Making the benchmark print the error body would settle
it next time.

NFR-10 therefore remains verified only for `frob/qwen3.5-instruct:latest`. Whether the
target should apply to the default model, or the default should change, is a decision for
Álvaro (not taken here).

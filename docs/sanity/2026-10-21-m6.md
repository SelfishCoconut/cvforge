## 4. Pattern inconsistency — WATCH (slightly degrading)

- Good: new modules follow the house style (module docstring citing FR, Google docstrings with
  Raises, `Depends(engine)`, `apply.NotFoundError` for 404, ADRs 0027 and 0028 landed with the
  work).
- **Low-Medium (4a, new)** three routes call a model and each handles failure differently:
  `api/chat.py:post_message` logs a warning and returns 502 via `failure_message(exc)`;
  `api/discovery.py:answer_question` and `submit_interview` return 502 via `failure_message(exc)`
  **without logging** (`discovery.py` has no `logger`); `api/cvs.py:edit_cv` returns 502 with a
  hand-built `f"the model could not plan the edit: {exc}"` (raw exception text, not
  `failure_message`, and no logging). Same concern, three styles; the reasoning-truncation hint
  in `failure_message` is lost in the edit route. *Remediation:* one `run_agent_or_502(...)`
  helper (or at least call `failure_message` and log in all three).
- **Low (4b, new)** `cv/validate.py:18` imports the underscore-prefixed `_set_status` from
  `cv/store.py`, and `tests/unit/test_cv_validate.py:445` does too. M5's 5b was fixed by making it
  private plus an AST test (`tests/unit/test_cv_final_gate.py`), which works, but a cross-module
  private import is a lint smell. Consider `store.mark_final` (public, documented as validator-only)
  with the call-site test unchanged.
- **Low (4c, new)** error-signalling style for `claim_problem` is still the bare
  `(code, message) | None` tuple (M5 4a), and `cv/edit.py:_reword` reads the message as
  `problem[1]`. A small dataclass would remove the magic index. Third consumer now.
- **Low (4d, new)** `api/discovery.py:submit_interview` returns `ChatResponse(conversation_id=0,
  message_id=0, ...)` for a transcript with no substantive answer. Zeros are sentinel ids that a
  client could mistake for a real conversation; a nullable id or a 200 with a distinct shape would
  be safer. The OpenAPI snapshot now pins the zeros.
- **Low (4e, new)** `answer_question` stores the user's answer as a conversation source
  (`store_message`) *before* the model runs; a 502 leaves an orphan conversation message with no
  proposal. Same as chat (pre-existing), so consistent; note only. `decline_question` correctly
  writes nothing.
- **Low (4f, carried M5 4c)** `render` writes `.tex`/`.txt` before the PDF compiles; `finalise` takes

## 5. Architectural drift — HEALTHY

**Boundaries.**
- `llm/` must not import `kb.apply`: no import (grep of `src/cvforge/llm` for `kb.apply` and
  `import apply` is empty). Checked: `llm/agents/interview.py` imports only `llm.*`;
  `llm/agents/cv_edit.py` imports `cv.store`.
- **Note (5a, new, Low)** `llm/agents/cv_edit.py:15` imports `cvforge.cv.store.StoredCv`, the first
  `llm -> cv` import. It is a read-only type used to render the prompt (`edit_prompt`), and `cv/`
  does not import `llm/`, so there is no cycle (verified: `grep llm src/cvforge/cv` empty). It does
  mean `llm/` now depends on a module that owns write access to `cv` tables. *Remediation:* move
  `edit_prompt` to `cv/edit.py` or `api/cvs.py` and let the agent module take a plain string, so
  `llm/` stays free of `cv/`. Also keeps `llm <-> match` (carried: `llm/agents/adjacency.py` imports
  `match.verdicts`, `match/verdicts.py` imports `llm.settings_store`) from becoming a pattern.
- `api/` must not bypass `kb/`: `api/discovery.py` imports `kb.apply` (errors only), `jobs.store`,
  `discovery.questions`, `llm.agents.interview`; no raw SQL. `api/cvs.py` adds `cv.edit` and
  `llm.agents.cv_edit`, nothing that touches a table.
- `kb/queries.py` must not write: no insert/update/delete.
- `discovery/questions.py` imports `jobs.store`, `kb.vocab`, `match.store`: read-only functions
  only (`get_posting`, `list_matches`); no model, no write.
- `cv/` imports no `llm` and has no model call, Agent or prompt. `cv/edit.py` reads via
  `kb.queries`, writes nothing itself; the new version goes through `save_cv`.

**Registered-writer registry: unchanged at 6 writers.** No module was added; `discovery/` and
`cv/edit.py` write nothing. Write-path tests pass (878 unit tests green). **Low (5b, carried)** the
module docstring of `tests/unit/test_write_path_invariant.py` still says the registry "starts
empty" (it holds six).

**Invariants.**
- Inv. 2/3/4 (discovery and interview): an answer is stored as provenance via `apply.record_source`
  / `store_message`, the interview agent uses the same read-only `tools.TOOLS` as ingest, the
  output becomes a pending proposal (`finish_proposal` -> `intake.propose`, origin `chat` or
  `interview`) and nothing commits without review. Decline writes nothing. Questions come from an
  untrusted posting but are fenced separately from answers (`_transcript`), and the prompt says
  only `<answer>` blocks state facts. Evidence for the proposal is the user's own answer text
  (`store_message` stores the answers, not the question), so a posting cannot be cited as the
  user's evidence. Sound.
- Inv. 5 (collaborative): **M5 5b is closed** (`_set_status` private, AST call-site test
  `test_cv_final_gate.py`). **M5 5d is addressed**: the first free-text path (`reword`) goes
  through `claim_problem` with `basis = reword`, which requires the current name/summary assertion
  and then `ungrounded_terms` over the entity's own and confirmed-neighbour texts. `save_cv`
  refuses `reword` claims when `mode` is automatic, and `validate_cv` flags `reword_in_automatic`,
  so the reword path cannot enter an automatic CV either by write or by presentation. The edit
  route saves with `GenerationMode.COLLABORATIVE` and returns validation issues; the CV is a
  draft until `finalize_cv`. `emphasize` can only add a skill whose `claim_source` exists and is
  confirmed. Structurally sound.
- **Medium-ish caveat to state plainly (5c, new):** the reword guard is a *heuristic* on tokens
  (the module docstring says so). It cannot catch a reworded line that changes meaning using only
  words already in the facts (for example reordering "led X, supported Y" into "led Y"), and
  `STRONG_STEMS` is a hand-kept English/Spanish/Russian list. Allowed by design (ADR-0028; final
  still needs review), but this is the one place invariant 5 rests on lexical matching rather than
  on schema, so adversarial tests matter (see 6b).

**Untrusted data.** CV lines are fenced (`fence("cv", ...)`) in `edit_prompt`; `cv_edit` agent has
no tools, so injected CV text cannot trigger a read or write. Posting text is fenced as `question`.
No new outbound calls.
